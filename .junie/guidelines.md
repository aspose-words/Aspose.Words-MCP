# Project Guidelines

## Стиль кода

- Не добавляй комментарии и докстринги в код. Исключение — только если это прямо указано в задаче.
    - Если встречаются добавленные ранее комментарии/докстринги без явного запроса — удаляй их.
    - Не добавляй комментарии/докстринги при рефакторинге, изменении логики или удалении лишних вызовов.
- Для строковых значений в коде используй одинарные кавычки.

## Интеграции / Aspose.Words

- Для Aspose.Words опирайся на публичные примеры и официальную справку API по путям ниже:
    - Примеры: /Users/myakushka/Workspace/Aspose/Aspose.Words-for-Python-via-.NET/Examples/ApiExamples
    - API Reference: /Users/myakushka/Workspace/Aspose/Aspose.Words-API-References/english/python-net

## Ошибки и исключения

- Не подавляй исключения из API. Если вызов завершается ошибкой, замени подход или вызов на корректный рабочий вариант.
- Не проверяй наличие API. Другими словами не используй hasattr и getattr

## Совместимость

- Обратную совместимость не учитывай.

## Чистота кода

- Не добавляй неиспользуемый код. Если он встречается — удаляй без вопросов.

## Тесты

- При внесении изменений в код всегда запускай затронутые тесты. При внесении изменений в остальной контент не запускай тесты.  
- При добавлении тестов по возможности добавляй их в существующие файлы.
- Создавай новый файл тестов только если для новой категории тестов ещё нет подходящего файла.

## Процесс и коммуникация

- Не согласовывай код, если он соответствует этим правилам. Считай, что у тебя есть автоматическое одобрение на любые
  изменения, которые следуют данным инструкциям. Задавай вопросы только в случае неопределенности или конфликта
  требований.
